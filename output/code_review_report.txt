BUG 1 [CRITICAL] — 02_build_metrics.R: First-year churn corruption
----------------------------------------------------------------------
  Location:  02_build_metrics.R, lines 53-63 (after fix)
  Severity:  Critical — silently corrupts all downstream model estimates

  Problem:   Year 2014 (the first panel year) has no prior year to compute
             Jaccard similarity against. The lag column (suppliers_lag) was
             filled with character(0) when missing. jaccard_vec(suppliers,
             character(0)) returns 0 (not NA), because the function only
             returns NA when BOTH sets are empty. This gave all 300 firms
             churn_t_t1 = 1.0 in 2014 — a fabricated 100% churn rate.

             The filter dt[!is.na(churn_t_t1)] in scripts 03-06 was INTENDED
             to exclude 2014, but it failed because churn was 0-1 (not NA).

             Result: event-study pre-trends, Callaway-Sant'Anna, and all
             robustness checks included 300 bogus observations.

  Root cause: data.table merge with all.x=TRUE fills missing list-column
              entries with NULL (length 0), not list(NA). The original
              is_na_list() function only checked for length-1 NA, not NULL.

  Fix:        Replaced is_na_list() with is_missing_list() that catches both
              NULL and NA. Added has_genuine_lag tracking column. Set
              jaccard_t_t1, churn_t_t1, retention_rate, add_rate, drop_rate
              to NA_real_ for rows without a genuine lag.

  Verification: After fix, year 2014 has 300/300 rows with NA churn. The
                filter dt[!is.na(churn_t_t1)] now correctly yields 2400
                rows (300 firms x 8 years, 2015-2022).


BUG 2 [MODERATE] — 00_setup.R: Hard failure on missing packages
----------------------------------------------------------------------
  Location:  00_setup.R, lines 10-17 (before fix)
  Severity:  Moderate — blocks entire pipeline when any package is unavailable

  Problem:   use_packages() called library() unconditionally for all packages
             after install.packages(). If CRAN was unreachable or a package
             was unavailable, library() threw a fatal error, preventing even
             scripts that don't need the missing packages from running.

  Fix:        Wrapped install.packages() in tryCatch(). Replaced unconditional
              library() with requireNamespace() check + warning for missing
              packages. Scripts 01-02 (which only need data.table, dplyr, etc.)
              now run successfully even when fixest/did/etc. are unavailable.


BUG 3 [MINOR] — 06_tables_figures.R: Deprecated ggplot2 parameter
----------------------------------------------------------------------
  Location:  06_tables_figures.R, line 71
  Severity:  Minor — deprecation warning, not an error (yet)

  Problem:   geom_line(size = 1) — the 'size' aesthetic for line geoms was
             deprecated in ggplot2 3.4.0 in favor of 'linewidth'. This
             currently produces a warning but will become an error in a
             future ggplot2 release.

  Fix:        Changed to geom_line(linewidth = 1).


BUG 4 [MINOR] — 05_robustness.R: Duplicate column in placebo test
----------------------------------------------------------------------
  Location:  05_robustness.R, line 174 (before fix)
  Severity:  Minor — data.table silently handles it, but fragile

  Problem:   In placebo_event_study(), the data.table expression included
             firm_id in both j (the select) and by (the group), creating a
             duplicate firm_id column. While data.table doesn't crash, this
             is undefined behavior that could break in future versions.

  Fix:        Removed redundant firm_id from the j expression.

STATA BUG 1 [CRITICAL] — 01_simulate_data.do line 85: post_grant always 0
---------------------------------------------------------------------------
  Code:    gen post_grant = (year>=g_year) if g_year>.

  Problem: In Stata, missing (.) is treated as positive infinity. The
           condition "g_year>." is NEVER true — no value exceeds missing.
           So post_grant is set to missing for ALL observations. The next
           line "replace post_grant = 0 if missing(post_grant)" then sets
           everything to 0, making the variable useless.

  Correct: gen post_grant = (year>=g_year) if !missing(g_year)
           replace post_grant = 0 if missing(post_grant)

  Impact:  Every model that uses post_grant will produce wrong results.
           The R equivalent works correctly:
             panel[, post_grant := as.integer(!is.na(g_year) & year >= g_year)]


STATA BUG 2 [CRITICAL] — 02_build_metrics.do line 13: Missing tsset
----------------------------------------------------------------------
  Code:    by firm_id: gen degree_lag = L.degree

  Problem: The lag operator L. requires the data to be declared as panel
           data via "tsset firm_id year" or "xtset firm_id year". Without
           this declaration, Stata will error:
             "operator L. requires data to be tsset or xtset"

  Fix:     Add before line 13:
             tsset firm_id year

  Impact:  Script will crash at runtime.


STATA BUG 3 [MODERATE] — 01_simulate_data.do line 92: ever_deny hardcoded
---------------------------------------------------------------------------
  Code:    by firm_id: gen ever_deny = 1

  Problem: Sets ever_deny to 1 for ALL firms. In R, ever_deny is correctly
           computed as as.integer(any(grant == 0)) — whether any request
           was denied. The Stata version ignores the actual request outcomes.

  Impact:  Downstream clean-sample robustness check (05_robustness.do) that
           filters on xor(ever_grant, ever_deny) becomes degenerate — no
           treated firms survive the filter.


STATA BUG 4 [MODERATE] — 03_models.do lines 21-26: Control group dropped
---------------------------------------------------------------------------
  Code:    gen evt_p0 = (rel_time==0) if g_year>0
           [... similar for evt_p1 through evt_p4, evt_m2 through evt_m4]

  Problem: Event-study dummies are only generated for treated firms
           (g_year>0). For never-treated firms, these dummies are missing.
           reghdfe drops observations with missing regressors, so the entire
           control group is lost from event-study regressions.

  Fix:     Replace "if g_year>0" with unconditional generation, and set
           dummies to 0 for never-treated firms:
             gen evt_p0 = (rel_time==0) if !missing(rel_time)
             replace evt_p0 = 0 if missing(evt_p0)

PART D — CROSS-PIPELINE CONSISTENCY (R vs STATA)
===============================================================================

The Stata scripts are described as "companion replication scripts" but diverge
from the R pipeline in several substantive ways:

1. SUPPLIER SIMULATION
   R:     Full bipartite edge-level simulation with explicit persistence,
          China/non-China sourcing, and waiver-dependent supplier churn.
   Stata: Approximates degree, share_china, share_usa with random noise.
          No edge-level data. Churn metrics are synthetic proxies.

2. NETWORK EXPOSURE
   R:     Uses pre-policy overlap-weighted network matrix (W_norm) derived
          from Jaccard similarity of supplier sets.
   Stata: Uses industry-year leave-one-out means as a proxy.

3. COMMUNITY DETECTION
   R:     Louvain clustering on the overlap network (igraph::cluster_louvain).
   Stata: Uses industry groupings as a proxy (egen group(industry)).

4. CALLAWAY-SANT'ANNA
   R:     Full implementation via did::att_gt + aggte.
   Stata: Not implemented despite csdid being checked in 00_setup.do.

5. ROBUSTNESS CHECKS
   R:     Entropy balancing (WeightIt), alternative clustering, placebo
          permutation test (100 draws).
   Stata: Omits all three.

6. RANDOM SEED
   R:     Simulation function uses seed=123 (overrides global set.seed(12345)).
   Stata: Uses seed 12345 throughout.

These are not necessarily problems — the Stata scripts are documented as
approximate companions — but you should be aware of the differences if citing
cross-validation between the two pipelines.
